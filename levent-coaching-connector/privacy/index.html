Levent Coaching Connector: Privacy Policy

Last updated: 4 October 2026

Levent Coaching Connector is a personal, owner-operated application run by its owner. This policy says what Google data the application accesses, what it does with it, where it is stored, who else receives it, how long it is kept, and how access can be revoked.

1. Who uses it

One person, the owner, with the owner's own Google account. The application is not offered to anyone else and collects nothing from any other person.

2. The Google permission requested from the owner

The OAuth consent screen asks the owner for only one permission (OAuth scope): https://www.googleapis.com/auth/drive.metadata.readonly, shown by Google as "See information about your Google Drive files". Technically, this permission allows an application to read metadata of files and folders visible to the account. It does not allow reading file contents, and it does not allow creating, changing, sharing, moving or deleting anything. No other permission is requested from the owner's Google account through the consent screen.

3. What the application does with it, and what else the system uses

The owner-authorized credential. It is more limited than the permission allows. With the owner's consent, the connector makes exact-ID metadata requests for the receipt folder, which the application's provisioning process created in a private Google Drive shared-drive mailbox controlled for the owner's workflow. Each request asks only for that folder's identifier and permission flags (whether the account may rename, share, trash, delete, move or add items), to confirm that the mailbox's permissions are as expected.

  • This credential does not request file or folder names or file contents.
  • It does not list, search or scan any other file, folder or drive.
  • It does not use the data for advertising, profiling, or any purpose other than confirming the mailbox's permissions.

Two dedicated service accounts. The private mailbox system also uses two dedicated service accounts that are not authorized through the owner's OAuth consent screen. A provisioning identity uses the Drive scope to create and maintain designated mailbox folders and control files and to configure and verify their permissions. A runtime-reader identity uses the Drive read-only scope to read metadata and download designated mailbox proposal files by exact ID. Before either service account is used in production, the provisioning gate verifies that its Drive access is restricted to the private mailbox resources required for the workflow. The application addresses those resources by exact ID and contains no Drive file-search or file-listing path.

4. What is stored and where

  • Permission flags. The returned values are evaluated in memory and are not stored.
  • Local records. The connector's capability check requests no file or folder names or file contents, and the returned capability flags are evaluated in memory rather than stored. The local database may store opaque Google Drive, file, folder and permission identifiers; application-generated or observed mailbox object names; principal email addresses; permission roles and inheritance details; provisioning state; recovery topology; and closed result, reason and audit-event codes needed for safe operation and recovery. It does not store Google Drive file content or the capability-flag values returned by the connector check.
  • Local runtime files. During processing and recovery, proposal and response-payload bytes are stored in private staging files and removed through the application's governed cleanup process. Prepared envelope and locator control files are stored in the private local runtime directory and remain there until the owner removes them by manual, reviewed cleanup; the application has no automatic removal of them. These files are not stored in the database. Under the current configuration both runtime directories are within the owner's Documents folder, so they are synchronized through iCloud Drive and included in the owner's encrypted Time Machine backups.
  • Where the local records live. In a database file on the owner's own computer, response_publication/publication.sqlite3. It is excluded from the code repository, but it is synchronized to the owner's private iCloud Drive and included in the owner's encrypted Time Machine backups.
  • Credentials. When the owner authorizes the connector, its credential will be stored outside Documents and other synchronized folders, in an owner-only directory, as a mode-0600 file excluded from Time Machine. It is used only to obtain short-lived access tokens from Google.

5. Who else receives it

Google processes the authentication and API requests. Apple processes the iCloud-synchronized runtime data as the owner's cloud-storage provider. Time Machine also stores encrypted historical copies on the owner's locally controlled external backup disks. The owner may deliberately share minimized, closed status or reason codes (for example "capability check passed" or a short reason code) with AI assistants, currently Claude by Anthropic and Codex by OpenAI, only when the owner decides to ask for operational, troubleshooting or security help. Such material contains no raw Google API response, capability value, Drive identifier, file or folder name, file content, email address, permission topology, credential or token, and the owner uses account or service settings that do not use submitted material to train generalized models. Google user data is not sold or used for advertising, and is disclosed to others only if required by law, for security investigation, or with the owner's own consent.

6. Retention and deletion

While the connector is in use, the local records in section 4 are kept in the database. When the connector is retired, the owner revokes the Google authorization and deletes the live credential within 24 hours. The connector's local records and files (database rows, staged files and control files) are not deleted automatically on retirement: they remain on the owner's own computer until the owner removes them by manual, reviewed cleanup, and no deletion deadline is promised. iCloud Drive synchronizes any such change, and historical Time Machine versions on the owner's local backup disks age out under the configured backup-retention lifecycle. This retention rule is independent of how long Google's own refresh tokens last.

7. Revoking access

The owner can revoke the application's access at any time at https://myaccount.google.com/permissions by choosing "Levent Coaching Connector" and then "Delete all connections".

8. Other people and children

The application is not intended for anyone other than its owner and collects nothing from anyone else.

9. Changes

Changes are posted on this page with a new date.

10. Google API Services User Data Policy

Levent Coaching Connector's use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.
